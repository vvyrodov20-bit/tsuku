## 1. Обновить проект на Vercel

1. Распакуйте архив. Откройте папку с `index.html`, `assets`, `api`, `lib`, `package.json` и `vercel.json`.
2. Замените содержимое корня своего репозитория этими файлами и папками. Папка `assets` обязательна: в неё вынесены картинки, стили и скрипты. Не загружайте только `index.html`.
3. В настройках проекта Vercel выберите Framework Preset: **Other**. Используйте Node.js **24.x**, как указано в `package.json`. Root Directory должен указывать на папку с этим файлом. Сборщик не нужен; не задавайте `dist` в Output Directory — это проект со статической главной и Vercel Functions.
4. Проверьте переменные из следующих разделов для Production. Для Preview используйте отдельные тестовые бота/чат и базу либо отдельный `TRACKING_NAMESPACE`, чтобы тестовые посещения не попали в рабочий чат.
5. После изменения переменных запустите Redeploy.

## 2. Подключить постоянное хранилище

Через [Upstash for Redis в Vercel Marketplace](https://vercel.com/marketplace/upstash/upstash-kv) подключите базу к существующему проекту. В переменных должны появиться REST URL и токен. Код поддерживает одну из пар:

| Предпочтительная пара | Совместимая пара |
|---|---|
| `UPSTASH_REDIS_REST_URL` | `KV_REST_API_URL` |
| `UPSTASH_REDIS_REST_TOKEN` | `KV_REST_API_TOKEN` |

Используйте REST credentials, а не TCP-строку `redis://…` и не read-only токен. Если интеграция создала только `REDIS_URL`, возьмите REST URL и REST Token в панели базы Upstash и добавьте их вручную под именами из левого столбца.

`TRACKING_NAMESPACE=gamehub:v2` — постоянный префикс ключей. Не меняйте его между обычными деплоями. Не удаляйте базу: в ней хранятся номера посетителей, ID Telegram-сообщений, связи кликов и постбэков. Эти записи намеренно не истекают сами. При росте трафика следите за объёмом хранилища; удаление истории означает потерю дедупликации и связи старых конверсий.

## 3. Telegram: одна карточка на посетителя

Сохраните существующие значения:

```dotenv
TELEGRAM_BOT2_TOKEN=ваш_токен_TrackerBot
TELEGRAM_BOT2_CHAT_ID=ваш_chat_id
TELEGRAM_TIMEZONE=Europe/Moscow
TELEGRAM_CONVERSIONS_SEPARATE=false
```

По умолчанию **все действия и конверсии обновляют одну карточку в боте №2**. Бот №1 не отправляет отдельные сообщения. В карточке:

- номер `#000001`, `#000002` и так далее;
- источник, страна, язык, канал, креатив и кампания;
- выбранные игры, число просмотров и партнёрских переходов;
- регистрация, ID игрока и число депозитов;
- последние 9 действий с временем. В базе хранятся последние 30 действий; количество просмотров, переходов и депозитов накопительное.

Сумма депозита показывается как передана партнёркой. Если валюта не передана, бот пишет об этом — он не определяет валюту суммы по стране.

При повторном открытии в том же браузере номер сохраняется. Кнопки «Скопировать ссылку» и «Открыть в браузере» переносят идентификатор и источник из TikTok/Facebook/Instagram. После открытия обычным браузером переносимый ID убирается из адресной строки и хранится локально.

**Номер относится к браузерному посетителю, а не к установленной личности.** Другой телефон, очистка хранилища или приватное окно создадут новый номер. При заблокированном хранилище идентификатор живёт до закрытия страницы. Без авторизации нельзя надёжно объединить все устройства одного человека. До появления известного click ID постбэк показывается как несвязанный с визитом; повторные события этого игрока обновляют ту же карточку.

Старые сообщения из прежней версии не удаляются. Первая новая карточка создастся один раз после обновления; сервер не принимает ID сообщения из браузера, поэтому старые карточки с недостоверным состоянием не используются.

Если нужно оставить отдельного бота для конверсий:

```dotenv
TELEGRAM_CONVERSIONS_SEPARATE=true
TELEGRAM_BOT1_TOKEN=токен_первого_бота
TELEGRAM_BOT1_CHAT_ID=chat_id_первого_бота
```

В этом режиме у посетителя будет одна общая карточка в боте №2 и одна дополнительная обновляемая карточка в боте №1. Номер посетителя одинаковый. Если обе пары реквизитов совпадают, второе сообщение не отправляется.

## 4. Настроить ссылки постбэков

Создайте длинный случайный секрет, например командой на своём компьютере:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Добавьте результат в переменную Vercel `POSTBACK_SECRET`. Ниже замените `YOUR-DOMAIN` на адрес сайта, а `YOUR_SECRET` — на этот секрет. Все фигурные скобки оставьте: их должна подставить партнёрская программа.

**Регистрация**

```text
https://YOUR-DOMAIN/api/postback/1win/registration?secret=YOUR_SECRET&event_id={event_id}&date={date}&hash_id={hash_id}&hash_name={hash_name}&source_id={source_id}&source_name={source_name}&amount={amount}&transaction_id={transaction_id}&country={country}&user_id={user_id}&sub1={sub1}&sub2={sub2}&sub3={sub3}&sub4={sub4}&sub5={sub5}&sub6={sub6}&sub7={sub7}&sub8={sub8}&sub9={sub9}&sub10={sub10}
```

**Первый депозит**

```text
https://YOUR-DOMAIN/api/postback/1win/first-deposit?secret=YOUR_SECRET&event_id={event_id}&date={date}&hash_id={hash_id}&hash_name={hash_name}&source_id={source_id}&source_name={source_name}&amount={amount}&transaction_id={transaction_id}&country={country}&user_id={user_id}&sub1={sub1}&sub2={sub2}&sub3={sub3}&sub4={sub4}&sub5={sub5}&sub6={sub6}&sub7={sub7}&sub8={sub8}&sub9={sub9}&sub10={sub10}
```

**Все депозиты (рекомендуется вместе с FTD)**

```text
https://YOUR-DOMAIN/api/postback/1win/all-deposits?secret=YOUR_SECRET&event_id={event_id}&date={date}&transaction_id={transaction_id}&user_id={user_id}&amount={amount}&country={country}&source_name={source_name}&sub1={sub1}&sub2={sub2}&sub3={sub3}&sub4={sub4}&sub5={sub5}&sub6={sub6}&sub7={sub7}&sub8={sub8}&sub9={sub9}&sub10={sub10}
```

Первый депозит и «Все депозиты» **обязательно должны передавать одинаковый настоящий `transaction_id`** для одной транзакции. До FTD общие события сохраняются как ожидающие и не вызывают уведомлений, после получения FTD её транзакция учитывается один раз, остальные переходят в редепозиты. Если FTD не придёт, ожидающие события останутся без классификации и уведомлений. При разных ID транзакции корректное сопоставление невозможно. Отдельный маршрут `redeposit` предназначен только для доказанно повторных депозитов; вместе с «Все депозиты» лучше не настраивать оба маршрута на одно и то же событие без надёжного ID. Секрет не отправляйте в чат и не публикуйте в открытом доступе.

**Повторный депозит**

```text
https://YOUR-DOMAIN/api/postback/1win/redeposit?secret=YOUR_SECRET&event_id={event_id}&date={date}&hash_id={hash_id}&hash_name={hash_name}&source_id={source_id}&source_name={source_name}&amount={amount}&transaction_id={transaction_id}&country={country}&user_id={user_id}&sub1={sub1}&sub2={sub2}&sub3={sub3}&sub4={sub4}&sub5={sub5}&sub6={sub6}&sub7={sub7}&sub8={sub8}&sub9={sub9}&sub10={sub10}
```

Также работают общий `/api/postback/1win?type=registration&…` и `/postback/partner?type=registration&…`; допустимы типы `registration`, `first_deposit`, `redeposit`. Тип нельзя определять только по `event_id`: код не предполагает неизвестное соответствие номеров событиям.

Если в партнёрке остались дополнительные прямые URL `api.telegram.org/.../sendMessage`, замените/отключите их. Этот сервер не может остановить сообщения, которые партнёрка отправляет напрямую в Telegram.

Для регистрации нужен настоящий `user_id`. Для депозитов дополнительно нужен `transaction_id`; если его нет — реальные `event_id` и `date`. Пустые/неподставленные обязательные поля не считаются успешной конверсией. Повторный transaction ID того же игрока не прибавляет депозит второй раз, даже если тип события изменился. Регистрация учитывается один раз на игрока.

## 5. Атрибуция игр и контента

По умолчанию `ONEWIN_CLICK_PARAM=sub1`:

| Поле | Значение |
|---|---|
| sub1 | Уникальный `click_id` для конкретного перехода |
| sub2 | Код источника: tt1, tt2, ig1, fb1 либо source |
| sub3 | channel: reels / story / post и т. д. |
| sub4 | creative: ваш идентификатор ролика |
| sub5 | Идентификатор нажатой кнопки |
| sub6 | falling-pickaxe / ice-fishing / tower-rush / game-hub |
| sub7 | Язык |
| sub8 | Страна |
| sub9 | Кампания |
| sub10 | Контент |

Если у вашей ссылки партнёрка возвращает click ID через другое `subN`, укажите его в `ONEWIN_CLICK_PARAM`. Значение, которое занимало это поле, переместится в sub1. Рекомендуется стандартная схема выше. Приёмник умеет найти `fp_…` в любом sub1–sub10.

Код добавляет параметры, но не может заставить партнёрскую ссылку их сохранить. После тестового перехода проверьте в партнёрке, что `sub1` вернулся без изменений. Без этого регистрация не сможет надёжно обновить карточку исходного посетителя.

Сохранены короткие адреса:

| Адрес | Название источника в Telegram |
|---|---|
| /tt1 | TikTok · Brasil |
| /tt2 | TikTok · Chile |
| /ig1 | Instagram · falling.pickaxe1 |
| /fb1 | Facebook · Matias Gonzales |

Пример ссылки для одного ролика:

```text
https://YOUR-DOMAIN/ig1?channel=reels&creative=ice_01&campaign=october&content=video_01
```

Новый явный источник меняет атрибуцию следующих действий, сохраняя номер браузерного посетителя. Конверсии получают канал/креатив из сохранённого конкретного перехода. Названия источников и список игр редактируются в одном файле `assets/catalog.js`. Для нового короткого адреса добавьте rewrite в `vercel.json`.

## 6. Заглушка TikTok / Facebook / Instagram

Все три приложения определяются по собственным признакам в User-Agent. Обычный Chrome или Safari не блокируется только из-за того, что посетитель пришёл по `/tt1` либо с Facebook.

На Android кнопка по нажатию пробует открыть ссылку в Chrome через intent. Если переход запрещён приложением или Chrome отсутствует, остаются инструкция и копирование. На iPhone код показывает инструкцию меню приложения и кнопку копирования. JavaScript не обещает автоматически открыть Safari. Заглушка не является обходом правил приложений: это обычное предложение открыть сайт во внешнем браузере.

Сохраняются язык, источник, канал, креатив и ID посетителя. Параметра, который принудительно выключает заглушку во встроенном браузере, нет. Если приложение скрывает или меняет признаки своего User-Agent, детектор может потребовать обновления в `assets/browser-utils.js`.

## 7. Просмотр на компьютере

`index.html` можно открыть двойным щелчком: дизайн, языки и разделы работают без внешних CDN и ожидания определения страны. В этом режиме переходы через сервер и постбэки недоступны; при нажатии игровой кнопки появится пояснение.

Для полной локальной схемы установите Node.js 24, откройте терминал в папке проекта, скопируйте `.env.example` в `.env`, заполните тестовые реквизиты и запустите:

```sh
npm run dev
```

Откройте `http://localhost:3000`. Устанавливать npm-пакеты не нужно. Секреты из `.env` локальный сервер не раздаёт. С настоящими реквизитами открытие локального сайта тоже отправляет события в Telegram, поэтому для проверки удобнее использовать тестовые.

## 8. Что проверено и что проверить после загрузки

`npm test` запускает автоматические тесты без доступа к настоящим ботам и базе. Используются подмены ответов Redis и Telegram и тестовая браузерная среда Node VM.

Проверены конкурирующие действия, fetch+beacon, перезагрузка, неизменённое сообщение, 429/403, удалённая карточка, потерянный ответ sendMessage, дубли регистраций и депозитов, привязка к игре и посетителю, секрет постбэка, все 42 словаря, RTL, определение приложений и перенос ID во внешний браузер.

Живое подключение к вашей партнёрке, Redis и Telegram в этой среде не запускалось. Визуальная проверка в реальном браузере и тест на физических устройствах не выполнялись. После деплоя:

1. Откройте `/tt1` в обычном браузере, переключите язык и раздел. В боте должна оставаться одна карточка, меняются её действия.
2. Нажмите разные игры. В карточке сохраняется номер, появляются названия игр. Проверьте итоговую партнёрскую ссылку.
3. Откройте ссылку непосредственно внутри TikTok, Facebook и Instagram, затем воспользуйтесь копированием во внешний браузер. Номер должен совпасть.
4. Через тест постбэков партнёрки отправьте регистрацию и депозит с реальным сохранённым sub1. Они должны обновить исходную карточку. Повторите тот же тест события: число депозитов не увеличится.
5. Откройте сайт в новом приватном окне. Появится другой номер.

## 9. Почему сообщения больше не множатся

ID Telegram-сообщения хранится на сервере. Обновления одного посетителя проходят через общую Redis-блокировку. Повторы имеют одинаковый ключ и не меняют счётчики повторно. Ошибка «message is not modified» считается успехом. Ограничение частоты и временные сбои приводят к повторной попытке редактирования, а не к новой отправке. Если сообщение действительно удалили, создаётся замена с тем же номером.

Редкий случай: Telegram мог принять новую карточку, но ответ с её ID потерялся. Bot API не даёт ключа идемпотентности для `sendMessage`, поэтому автоматическая повторная отправка способна сделать дубль. В этой версии неоднозначная отправка блокируется с кодом `telegram_delivery_uncertain`, события остаются в базе. Восстановление: возьмите `visitor_id` из Redis и ID уже созданного сообщения, затем на своём компьютере с заполненной `.env` выполните:

```sh
npm run reconcile-card -- v_ВАШ_ID ID_СООБЩЕНИЯ 2
```

Следующее событие или повтор постбэка обновит привязанную карточку. Не запускайте восстановление с чужим message ID. Если сообщение точно не было доставлено, оператор может снять `deliveryPending` у этой карточки в Redis, чтобы следующая попытка создала её. Не снимайте флаг до проверки чата.

Если отсутствуют переменные или недоступна база, API возвращает 503. Посещения повторяются из клиентской очереди, постбэки возвращают ошибку для повторной доставки партнёркой. Переход на корректную партнёрскую ссылку остаётся доступным при сбое аналитики; если база недоступна именно в этот момент, связь перехода может быть потеряна. История уже записанных событий не пропадает при ошибке Telegram. Отдельный фоновый обработчик повторов не настроен: обновление после сбоя выполняется следующей попыткой/событием.
